## 冲突与风险

1. 第 57 章“第一阶段”包含 Room/FastAPI，和用户本次范围不同：本次不创建这些实现或伪造对应报告。
2. 第 54 章第 3 天要求黑名单 BLOCK 测试，属于规则阶段：WP-01 只验证固定 ALLOW 与系统方向处理，不写虚假名单测试。
3. 第 46 章与 WP-03 的标准模式动作/分数不一致；WP-04 按模式降级又与未知默认 ALLOW 冲突；二次来电减分有 8/10 分不同版本。这些列为后续待裁定事项，本次不选阈值。
4. Android 无 READ_CONTACTS 时一般只筛查非联系人；隐藏/未知等 presentation 的电话也可能不送入服务。两台设备的 20 次回调基准必须用系统支持的普通陌生号码，不能保证“所有来电都收到回调”。
5. 角色授权不等于筛查测试通过；系统实际响铃和记录仍需真机观察。onScreenCall 收到去电时不调用入站响应。
6. 本机 SDK 只有 API 36。本次明确固定 compile/target 36，未把它宣称为当日最新稳定版；与计划书“当前稳定 SDK”存在待确认的版本差异，发布前重新核对。
7. 计划要求初始 Git 提交；本轮先建立工程与验证证据，不自动发布或提交版本，不把 Git 提交状态当功能验收。

## 完成标准

- 工程能用固定工具链产生 debug APK；基础测试与 lint 通过。
- 三状态准确：不支持、未授权、已授权；用户取消申请不会误报成功；设置更换角色后返回 App 显示失效。
- 入站回调只发一次 ALLOW，不静音、不拒接、不隐藏通知/通话记录；日志无号码。
- 两家厂商各 10 次普通陌生来电，回调成功率 100%，P95 < 2000 ms，并观察正常响铃/接听。
- 验证进程自然终止后系统重新绑定，区别于强制停止 App。
- 真机证据与用户确认完成前，不进入 WP-02。单测/构建通过不能代替真机验收。
